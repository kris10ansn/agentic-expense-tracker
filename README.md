# AI Expenses

This reference branch includes the [capture outcome prototype](prototypes/capture-failure/README.md), with the **Capture failed**, **Review needed**, and pending-entry designs.

TypeScript monorepo with two Bun workspaces:

- `apps/api`: tRPC API on Bun, Drizzle ORM for PostgreSQL, and Zod validation.
- `apps/web`: React, Vite, Tailwind CSS, and tRPC with TanStack Query.

Both apps share `tsconfig.base.json` and the root `biome.json`. The web app imports the API router as a type through `@ai-expenses/api`; server code stays out of the browser bundle.

## Start development

Install [Bun](https://bun.com/docs/installation) 1.4.4 or newer and Docker with Docker Compose.

Run these commands from the repository root:

```sh
cp .env.example .env
bun install
bun run db:up
```

In `.env`, set `BETTER_AUTH_SECRET` to a value generated by `openssl rand -hex 32`, and set `AUTH_ALLOWED_EMAILS` to the comma-separated email addresses that may use the app. Set `GOOGLE_GENERATIVE_AI_API_KEY` for expense extraction. Then apply migrations and create your first account:

```sh
bun run db:migrate
bun run account create you@example.com
bun run dev
```

The account command prompts for a password without displaying it. Use 12–128 characters. Open <http://localhost:5173> and sign in. Mobile uses bottom navigation; desktop uses a sidebar. Expenses have daily totals inside collapsible months.

**Migration `0004` deletes all existing expenses, collections, and captures.** They are unowned test data; new records belong to the signed-in user. Back up anything you want to keep before applying it.

TanStack Router owns the routes and typed collection/search filters:

- `/`: recent expenses, pending capture requests, and the capture dock.
- `/expenses`: saved expenses, search, and collection filtering.
- `/collections`: collection management.
- `/settings`: signed-in email, password change, and sign out.
- `/login`: email/password sign-in.

The comparison routes, variant controls, and rejected components have been removed. Pending captures appear only on Home and never contribute to saved expense totals.

The workspace starts with no expenses, collections, or pending captures. The mock API has been removed. Create, update, and delete callbacks log their inputs to the console until API mutations are connected; they do not change or persist records.

Capture controls remain visual only. Text grows from a single line, and you can choose a collection. Holding the recording button with a pointer, Space, or Enter previews the animation, with reduced-motion support. Recording, camera, gallery, and text submission do not access devices or create expenses.

### Web structure and data loading

- `src/routes`: file-based routes, loaders, and URL validation. The Vite plugin generates `routeTree.gen.ts`; do not edit it by hand.
- `src/pages`: page composition.
- `src/features`: capture, expense, collection, and workspace components. Shared buttons, inputs, dialogs, and layout live in `src/components`.
- `src/features/workspace`: layout, dialog state, mutations, and notifications. The shell and page headings render immediately while data sections load.

Data sections use TanStack Query and the tRPC options proxy to read expenses and collections from a shared cache. Lists and selectors show skeletons during initial loading and local retry messages on failure. Background refreshes preserve cached content and capture drafts. List components receive ordinary data and callbacks; workspace context owns dialog actions. Dialogs load their required data when opened, and mutations invalidate the affected queries after writes.

Vite renders the shared `LoadingScreen` component into the initial HTML in development and production. The HTML includes the Tailwind utilities needed by that screen, compiled from the same stylesheet as the app. A small bootstrap module loads React and the application CSS asynchronously. The application entry point dismisses the startup screen on the router's first `onRendered` event, then unsubscribes. Routes use the shared loading screen while pending; individual pages do not manage startup cleanup. Failed application downloads show a reload action. This makes the loading screen visible before application assets arrive; it does not make the session request finish sooner.

The backend exposes AI extraction and saved expense and collection CRUD. The UI derives extraction fields and categories from the router type; record and create-input types in `src/lib/expenses.ts` are inferred from the CRUD endpoints. The UI uses collection titles, purchase timestamps, optional collections, and totals grouped by currency.

The API listens on <http://localhost:3001>, serves tRPC at `/trpc` and Better Auth at `/api/auth`, and exposes a public process health check at `/health`. Sign-in and workspace access require the API.

`bun run dev:api` and `bun run dev:web` start the apps separately. Both read settings from the root `.env`. Vite proxies `/trpc` and `/api/auth` to the API using `API_PORT` and keeps database settings out of browser code.

Override either development port or both:

```sh
bun run dev --web-port 5174
bun run dev --api-port 3002
bun run dev --web-port 5174 --api-port 3002
```

Unspecified ports keep their existing settings. The defaults are 5173 for the web app and 3001 for the API. Port arguments must be integers between 1 and 65535 and override environment settings. Changing the API port also updates Vite's proxies. `--web-port` sets the matching `BETTER_AUTH_URL` for that run.

To start only the frontend on a custom port, use Vite's `--port` option:

```sh
bun run dev:web --port 5174
```

When starting the apps separately, set `BETTER_AUTH_URL=http://localhost:5174` in the API environment too.

## Manage accounts

Better Auth runs inside the API and stores users and sessions in PostgreSQL. There is no public signup, email delivery, social login, or admin dashboard. Account creation and password recovery use a local command with database access:

```sh
bun run account create you@example.com
bun run account reset-password you@example.com
```

Add the exact email address to `AUTH_ALLOWED_EMAILS` first. The commands normalize email case and prompt for the password; do not pass passwords as command arguments. Resetting a password preserves the user's records and revokes all their sessions. Settings lets users change their own password and revokes their other sessions.

Remove an address from `AUTH_ALLOWED_EMAILS` and restart the API to block that account, including existing sessions. Records remain in the database. Accepted AI extraction continues after logout and saves to the original account; its progress and results remain private.

Sessions use HTTP-only cookies and last approximately 30 days, renewed during use at most once per day. Signing in or out reloads the page to clear cached records and drafts. All expense, collection, and capture operations enforce ownership on the server.

## Check changes

```sh
bun run check
bun run typecheck
bun run test
bun run build
```

`bun run test` runs API tests and web tests for expense forms, formatting, grouping, URL filters, and capture cache updates. AI extraction tests mock the provider's HTTP responses and do not require an API key.

PostgreSQL integration tests run when `TEST_DATABASE_URL` is set. These cover authentication, session revocation, cross-user access, collection persistence, expense ordering, the capture lifecycle, startup recovery, and watcher shutdown. Each suite creates, migrates, and drops its own temporary database, so the database user must have permission to create databases.

With the local database running and the default credentials from `.env.example`, run the full suite:

```sh
TEST_DATABASE_URL=postgresql://ai_expenses:ai_expenses@127.0.0.1:5432/ai_expenses bun run test
```

Adjust the URL if your local database settings differ. Without `TEST_DATABASE_URL`, the PostgreSQL integration tests are skipped.

`bun run check` checks formatting, lint rules, and imports with Biome. Use `bun run check:fix` to apply safe fixes, or `bun run format` to apply formatting only.

With the web preview or development server running, the startup browser check verifies rendering with all application assets held pending, mobile layouts, reduced motion, session retries, redirects, and failed asset recovery. It runs through Bun with the web workspace's Playwright development dependency and is included in `bun run typecheck`. Install Chromium once, then run the check:

```sh
bun run --cwd apps/web playwright install chromium
WEB_URL=http://127.0.0.1:4173 bun run --filter @ai-expenses/web test:startup
```

Set `CHROMIUM_PATH` to use a system Chromium executable instead of installing one, and `SCREENSHOT_DIR` to save screenshots. Run the same check against the development server by changing `WEB_URL`.

With the database and both apps running, verify the HTTP connection through Vite to tRPC and PostgreSQL:

```sh
bun run smoke
```

## Run the builds locally

After `bun run build`, start the API and web preview in separate terminals. The auth URL must match the browser's origin:

```sh
BETTER_AUTH_URL=http://localhost:4173 bun run --filter @ai-expenses/api start
bun run --filter @ai-expenses/web preview
```

Open <http://localhost:4173>, or run `WEB_URL=http://localhost:4173 bun run smoke` to check the builds. Vite preview is for local verification. When deploying, serve `apps/web/dist`, fall back to `index.html` for client routes, and route `/trpc` and `/api/auth` to the running API under the same origin. Set `BETTER_AUTH_URL` to that public HTTPS origin and keep `BETTER_AUTH_SECRET` stable and private. Never cache auth or tRPC responses. The API bundle is `apps/api/dist/index.js` and runs with Bun.

Better Auth limits repeated authentication attempts in memory within each API process. Keep the API behind a trusted reverse proxy that overwrites `X-Forwarded-For` with the client's address; do not expose it directly to the internet with untrusted forwarding headers. This setup assumes a single API process.

## Manage the database

```sh
bun run db:up
bun run db:logs
bun run db:shell
bun run db:down
```

Docker runs PostgreSQL 18 on `127.0.0.1:5432`. Compose stores data in a named volume, which `db:down` preserves. The default credentials in `.env.example` are for local development.

If port 5432 is occupied, change `POSTGRES_PORT` and the port in `DATABASE_URL` in `.env`. Keep the database name and credentials in `DATABASE_URL` consistent with `POSTGRES_*`. PostgreSQL applies initialization credentials only when the volume is empty; changing `.env` does not update an existing database user.

## Change the database schema

Define app tables in `apps/api/src/db/schema.ts` and Better Auth tables in `apps/api/src/auth/schema.ts` using `drizzle-orm/pg-core`. Then generate and apply migrations:

```sh
bun run db:generate
bun run db:migrate
```

Commit generated migrations under `apps/api/drizzle` alongside schema changes. The migration runner uses Drizzle's Bun SQL adapter, matching the API's database connection.

The public status endpoint checks the database through Drizzle with `SELECT 1`. Zod validates database, API, and authentication settings when the API starts.
